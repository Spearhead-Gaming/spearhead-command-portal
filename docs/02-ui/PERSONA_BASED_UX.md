# Persona-Based UX

Persona UX tailors presentation for common responsibilities without creating separate apps.

## Supported Personas

- Community Member
- Patrol Leader
- Unit Leadership
- S1 / Personnel Staff
- S3 / Operations Staff
- Deployment Creator
- Zeus
- Training Staff
- Command Staff
- Community Manager
- Administrator
- Developer

## UX Rules

- Permissions decide what a user may access.
- Personas decide what appears first.
- Multi-persona users may switch workspace context.
- Single-persona users should not see a large persistent switcher.
- Secondary details stay available through existing pages, drawers, tabs, and collapsed sections.

## Page Goals

Each persona workspace should answer:

1. What is this workspace for?
2. What needs attention?
3. What action should I take next?

## Not Applicable vs Unauthorized

Unavailable work should be framed clearly:

- Unauthorized means the user lacks permission.
- Not applicable means the user has no matching responsibility.
- No current work means the user is authorized but has nothing pending.
