# Design Principles

## 1. Spearhead First

The system exists to serve Spearhead Gaming.

When there is a conflict between generic flexibility and Spearhead usability, Spearhead usability wins.

## 2. Configurable, Not Generic

The project should not become a generic Milsim SaaS product.

However, important structures should remain configurable:
- Units
- Ranks
- Positions
- Qualifications
- Discord servers
- Discord channel mappings
- Permissions
- Campaign statuses
- Attendance statuses

## 3. Discord First

If a simple action can happen in Discord, it should.

Examples:
- RSVP
- View profile
- View qualifications
- Receive reminders
- Receive announcements

## 4. Portal as Source of Truth

The portal owns official data:
- Rosters
- Units
- Ranks
- Qualifications
- Attendance
- Campaigns
- Events
- Documents
- Logs

## 5. Ease of Use

Every page should have a clear primary action.

Common tasks should take less than 30 seconds.

## 6. Modular by Default

Modules should be isolated enough to expand or replace later as Spearhead changes.

## 7. Role-Based Experience

Members, unit leaders, S3, and administrators should not see the same dashboard.

## 8. Automation Before Administration

If a task is repeated often, design it for automation.

## 9. Search Everything

Users should be able to quickly find members, units, qualifications, events, campaigns, and documents.

## 10. Mobile Friendly

Leadership should be able to review and perform common actions from a phone.
